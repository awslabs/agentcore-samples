# Databricks per-user delegation: use native token exchange

Start with [Databricks per-user identity using native Gateway token exchange](../databricks-dbsql-native-obo/). It explains how to configure the upstream issuer, Databricks federation policy and outbound `TOKEN_EXCHANGE` grant, including when `NO_CLIENT` is required. Use its identity check before querying synthetic data: success means the **end user**, not a shared service principal, reaches the workspace. The [M2M target](../databricks-dbsql-agentcore-gateway/) is a different trust model and is not a fallback for per-user access.

The [earlier interceptor implementation](https://github.com/awslabs/agentcore-samples/tree/5cca7e89f8109115766b9f7df3f0b7e98ca9eab1/03-integrations/data-platforms/databricks-dbsql-per-user-delegation) deployed a request Lambda to perform the exchange. That Lambda and its monitoring/deployment steps are not part of the native flow. Do not detach an existing interceptor until the owner has verified the native configuration, identity of more than one test user, and denial of unauthorized data access. Do not expose a target temporarily with broader M2M permissions during migration.

Existing resources are not removed by this change. Use your original Gateway/target, provider and Lambda IDs and deployment records for cleanup. Revoke only dedicated grants; keep shared identity providers and workspace infrastructure intact.
